# Grid

Командные Kanban-доски: несколько проектов, неограниченные колонки,
перетаскивание, подзадачи, дедлайны, файлы и комментарии. Плюс те же
задачи на диаграмме Ганта и в календаре. Данные — в Supabase,
страница — на GitHub Pages.

**Адрес доски:** https://iliaeov-tech.github.io/grid/grid.html

---

## Что умеет

**Проекты.** Кнопка боковой панели слева от логотипа (или клик по самому
логотипу) выдвигает список проектов: переключиться, создать, удалить.
Каждый проект — самостоятельная доска со своими колонками и задачами.
Список участников общий для всех проектов.

**Вкладки над колонками.** Доска · Диаграмма Ганта · Календарь ·
Заметки и файлы · Архив. Гант и календарь строятся по датам той же доски.

**Задача.** Чекбокс с зачёркиванием, статус, тип задачи с иконкой,
приоритет с цветом, ответственный, даты начала и дедлайна, подзадачи,
вложенные файлы, описание и комментарии с автором и временем. Меню «⋮»
на карточке: открыть, добавить подзадачу, убрать в архив, удалить.

**Типы задач.** Стандартные (Отчёты, Обучение, Улучшайзинг, Идея,
Заметка, Срочно) плюс свои: «+ Свой тип» в панели задачи — название,
цвет и иконка из набора. Свои типы хранятся в проекте, их можно
переименовать и удалить (карандаш рядом с «+ Свой тип»).

**Статусы.** Общие для всех проектов. «Настроить» рядом с полем статуса:
добавить, переименовать, перекрасить, удалить. Если статус стоит у задач,
при удалении доска спросит, на какой статус их перевести. Статус «Готова»
ставится выполненным задачам, поэтому его можно переименовать, но не
удалить.

**Подзадачи.** Это отдельные карточки со своим чекбоксом, меню «⋮»,
дедлайном, приоритетом и ответственным; открываются в такой же панели,
как задача. На карточке родителя — прогресс «3/11» и стрелка, которая
раскрывает подзадачи прямо в колонке. Подзадача живёт под родителем и
переезжает вместе с ним. Через «⋮» её можно сделать отдельной задачей.

**Колонки.** Создать, перетащить и всё остальное — через меню «⋮» в
шапке колонки: переименовать, архивировать все задачи или только
выполненные, переместить в другой проект (вместе с задачами), дублировать
(копия встаёт справа, с задачами и подзадачами, но без комментариев и
файлов), разово отсортировать задачи — по дедлайну, ответственному, дате
создания, выполненности, названию, приоритету, типу или статусу, по
возрастанию или убыванию. Там же перенос выполненных задач и цвет шапки:
ряд пастельных и ряд насыщенных цветов.

**Архив.** Задача уходит в архив вместе с подзадачами и пропадает с
доски, Ганта и календаря. Во вкладке «Архив» её можно вернуть в конец
своей колонки или удалить навсегда.

**Календари.** В панели задачи с датами — «Google Календарь» (готовое
событие) и «Файл .ics» (для Outlook, Apple Календаря и других). А в
настройках (шестерёнка внизу боковой панели) каждый получает личную
ссылку для подписки: задачи с датами сами появляются в его Google
Календаре или Outlook — только свои или все задачи команды. Календарь
забирает изменения раз в несколько часов (Google — бывает и до суток),
ускорить это нельзя; правки в календаре в доску не возвращаются.
Событие ведёт ссылкой прямо на задачу в доске.

**Заметки проекта.** Во вкладке «Заметки и файлы» кнопка «+ Заметка»
создаёт новую. У заметки есть название, цвет и тип: стандартные
(Заметка, Договорённость, Встреча, Инструкция, Ссылки, Идея) плюс свои,
как у задач.

### Две особенности, о которых стоит знать

Отметка «выполнено» **переносит задачу в другую колонку** — по
умолчанию в следующую. В меню колонки можно выбрать другую колонку,
в том числе в другом проекте, или выключить перенос: тогда задача
остаётся на месте. Снятие галочки задачу не возвращает. Подзадачи при
выполнении никуда не переезжают.

Перетаскивание рассчитано на мышь. На телефоне задачу переносят через
поле «Колонка» в панели задачи.

## Что нужно сделать один раз

Пока эти шаги не выполнены, доска открывается в демо-режиме: интерфейс
работает целиком, но задачи лежат только в браузере и коллеги их не видят.

### 1. Создать проект Supabase

[supabase.com](https://supabase.com) → New project.

### 2. Создать таблицы и хранилище

Supabase → **SQL Editor** → вставить целиком файл
[`supabase-schema.sql`](supabase-schema.sql) → **Run**.

Скрипт создаёт таблицы и пять стандартных статусов, приватный бакет
`grid-files` для вложений, включает живые обновления и закрывает данные:
читать и писать может только вошедший пользователь. Он рассчитан на
новый проект Supabase.

### 3. Включить вход через Google

**а) Google Cloud.** [console.cloud.google.com](https://console.cloud.google.com)
→ APIs & Services → Credentials → Create credentials → **OAuth client ID** →
тип **Web application**. В поле *Authorized redirect URIs* вставить:

```
https://<ВАШ-ПРОЕКТ>.supabase.co/auth/v1/callback
```

Скопировать **Client ID** и **Client secret**.

**б) Supabase.** Authentication → Providers → **Google** → включить,
вставить Client ID и Client secret → Save.

**в) Supabase.** Authentication → URL Configuration:

- *Site URL:* `https://iliaeov-tech.github.io/grid/grid.html`
- *Redirect URLs:* добавить туда же `https://iliaeov-tech.github.io/grid/grid.html`

### 4. Прописать ключи в доску

Supabase → Project Settings → API. Оттуда нужны **Project URL** и ключ
**anon**. Вставить их в [`grid.config.js`](grid.config.js) и закоммитить.

Через минуту после пуша доска заработает по адресу выше.

> Ключ `anon` не секретный: он рассчитан на публикацию в браузере и не даёт
> обойти права доступа. Данные защищают вход через Google и правила RLS.
> Ключ `service_role` в этот репозиторий класть нельзя — он даёт полный
> доступ к базе в обход всех правил.

### 5. Подписка на календарь (по желанию)

Ссылки на календарь из настроек отдаёт функция Supabase из файла
[`supabase/functions/grid-calendar/index.ts`](supabase/functions/grid-calendar/index.ts).
Её нужно развернуть один раз — любым из двух способов.

**В браузере.** Supabase → Edge Functions → Deploy a new function →
Via Editor. Имя — `grid-calendar`, вместо примера вставить содержимое
файла целиком → Deploy. Затем в настройках функции выключить проверку
JWT (Verify JWT / Enforce JWT verification).

**Из командной строки** (нужен Node.js), в папке репозитория:

```
npx supabase login
npx supabase functions deploy grid-calendar --no-verify-jwt --project-ref <ВАШ-ПРОЕКТ>
```

`<ВАШ-ПРОЕКТ>` — часть адреса до `.supabase.co`.

Проверка JWT выключается потому, что приложения календаря не умеют
входить через Google; задачи по ссылке защищает секретный токен в ней.
Ключи функции не нужны — Supabase подставляет их сам. Если доска
переедет на другой адрес, задайте его в Edge Functions → Secrets как
`GRID_URL`, чтобы ссылки из событий вели на новое место.

Как проверить: создайте ссылку в настройках доски и откройте её в
браузере — должен скачаться или открыться текст, начинающийся с
`BEGIN:VCALENDAR`.

### 6. Позвать команду

Отправьте коллегам ссылку. Заходят через Google, отдельных приглашений
в Supabase не нужно. Затем в доске: значок участников в шапке →
добавить людей → каждый выбирает себя кнопкой «Кто вы?».

## Как устроено

| Файл | Назначение |
|---|---|
| `grid.html` | Всё приложение: разметка, стили, логика |
| `grid.config.js` | Адрес проекта Supabase и публичный ключ |
| `supabase-schema.sql` | Таблицы, права доступа, бакет файлов, живые обновления |
| `supabase/functions/grid-calendar/index.ts` | Календарь для подписки по секретной ссылке |
| `index.html` | Перенаправление с корня на `grid.html` |

Хранилище спрятано за адаптером (`supaStore` / `localStore` в `grid.html`)
с четырьмя операциями: `subscribe`, `set`, `update`, `del`. Смена базы —
это замена одного адаптера, остальной код её не видит. Соответствие
полей в браузере колонкам базы задаёт одна таблица `MAP`.

Подзадача — обычная строка `cards` с `parent_id`. Свои типы задач и
заметок лежат в `kinds` и привязаны к проекту, статусы — в общей
таблице `statuses`.

Порядок карточек и колонок задаёт дробное число `pos`: при переносе
пересчитывается только сама карточка.

Файлы лежат в приватном бакете `grid-files`; ссылка на скачивание
выдаётся на две минуты. В демо-режиме вложения хранятся прямо в браузере
и ограничены 400 КБ.

## Ограничения

- Одновременная правка одного поля разными людьми разрешается по принципу
  «последний сохранил — тот и прав».
- Классы CSS в `grid.html` живут в одном пространстве имён: перед тем как
  добавить модификатор вроде `chip talk`, проверьте, что такого класса нет
  у блока — иначе он унаследует чужую раскладку.
