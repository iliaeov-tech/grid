# Grid

Одно приложение, два режима:

- **Grid Work** — Kanban-доски: несколько проектов, неограниченные
  колонки, перетаскивание, подзадачи, дедлайны, файлы и комментарии, плюс
  те же задачи на диаграмме Ганта и в календаре.
- **Grid Life** — личный календарь задач.

Страница — на GitHub Pages.

**Адрес:** https://iliaeov-tech.github.io/grid/grid.html

## Как Grid работает сейчас: только на этом устройстве

Оба режима хранят данные в браузере этого устройства (IndexedDB, с
запросом постоянного хранения) и **ничего не отправляют на сервер**. Вход
не нужен, Grid открывается сразу и работает без интернета; его можно
установить на главный экран.

- Сайт обращается только к своим файлам: шрифты (Golos Text, Unbounded,
  JetBrains Mono) лежат в папке [`fonts/`](fonts/) вместе с текстом
  лицензии, сторонних библиотек и CDN нет.
- Наружу Grid выходит только по действию человека, и это подписано:
  «Google Календарь» в задаче передаёт название и даты задачи в его
  Google Календарь, «Сотрудничество и отзывы» открывает Telegram.
- При первом запуске Grid Work показывает пример с кнопкой «Очистить и
  начать с нуля». Данные прежнего демо-режима (localStorage) при первом
  запуске переезжают в новое хранилище без потерь.
- На компьютере (Chrome, Edge, Яндекс Браузер — где браузер умеет работать
  с папками) данные хранятся в выбранной папке Grid, а браузер — рабочая
  копия: очистка браузера их не сотрёт, а папка в Яндекс Диске, OneDrive
  или Google Диске — ещё и облако.
- Где папки нет (iPhone, другие браузеры), данные пропадут, если очистить
  браузер или сменить устройство, поэтому Grid напоминает сохранить
  резервную копию — один файл с Grid Work и Grid Life; на телефоне он
  сразу уходит в меню «Поделиться». От ошибок везде защищают снимки: раз
  в день Grid сам сохраняет состояние на устройстве.

Совместная работа через сервер — вход, команда с ролями, приглашения,
push-уведомления, подписка на календари, push-напоминания Grid Life —
написана и проверена, но выключена настройкой `collab: false` в
[`grid.config.js`](grid.config.js). Пока она выключена, этот код не
загружается и ничего не показывает. Как её включить — раздел
«Совместная работа (второй этап)» ниже.

## Что умеет

**Режимы.** Переключатель справа от логотипа меняет режим: «Grid Work»
(синий акцент) или «Grid Life» (зелёный). Переключение мгновенное,
приложение запоминает последний режим на этом устройстве (или всегда
открывается в Grid Life — это настройка Grid Life). В Grid Life
скрыто всё рабочее — проекты, участники, фильтры и вкладки доски.
Оба режима открываются сразу, без входа (при совместной работе Grid Work
просит войти). Ссылка на задачу из календаря (`#task=…`) всегда
открывает Grid Work.

**Grid Life — личный календарь.** Виды: список по дням (основной),
день, неделя, месяц; кнопка «Сегодня». Задача: название, дата, время
или «весь день», необязательное время окончания, тип с иконкой и цветом
(Дела, Встреча, Здоровье, Спорт, Покупки, Учёба, Семья, Финансы плюс
свои), приоритет, файлы, короткое описание, чекбокс выполнения.
Невыполненные задачи прошлых дней — в блоке «Просрочено» вверху
списка, их можно перенести на сегодня по одной или все сразу; задачи
без даты — в «Без даты». Создать задачу — кнопка «+», касание по дню в
списке, по времени в дне и неделе, второе касание дня в месяце. В
боковой панели — виды и типы: снятая галочка скрывает задачи типа.

**Многодневные задачи.** Переключатель «Несколько дней» под датой
показывает поле «Дедлайн» — последний день срока (не раньше даты
начала). Со временем начало относится к первому дню, окончание — к дню
дедлайна. Новая дата начала переносит срок целиком. В месяце на
компьютере задача — полоса через дни, как в календаре Grid Work, на
телефоне — точки во всех днях срока; в неделе и дне — полоса в строке
«весь день». В списке — в день начала с подписью «до 3 нояб», а пока срок
идёт — в «Сегодня» с пометкой «идёт, до 3 нояб». Одна галочка закрывает
задачу целиком, просроченной она становится только после дедлайна, «На
сегодня» переносит весь срок. Повтор переносит весь срок (например, 3 дня
каждый месяц). Задачи и копии без дедлайна — однодневные.

**Повторяющиеся задачи.** Каждый день, каждую неделю (по выбранным дням),
каждые 2 недели, каждый месяц, каждый год или свой интервал — каждые N
дней, недель, месяцев или лет. Окончание: бессрочно, до даты, после N
раз, плюс быстрые «Месяц» и «Год». Если в месяце нет нужного числа
(31-е, 29 февраля), повтор пропускается, как в Google Календаре.
Выполнение повтора отмечает только его. Изменение или удаление
повторяющейся задачи спрашивает: «Только эту», «Эту и последующие» или
«Все». В «Просрочено» от серии попадает только последний пропущенный
повтор.

**Напоминания.** В настройках — о каких задачах напоминать (обо всех,
только о важных — с высоким и срочным приоритетом, только о выбранных,
не напоминать), напоминание по умолчанию (в момент начала, за 5, 15, 30
минут, за час, за день) и время для задач на весь день (по умолчанию
9:00). В задаче можно добавить несколько напоминаний, своё время («за N
минут, часов или дней») или убрать их; «Как в настройках» возвращает
общее правило. Напоминания считаются от начала задачи; у многодневной
есть ещё «В день дедлайна» — в этот день во время напоминаний о задачах
на весь день. Пока Grid открыт, он напоминает сам — системным
уведомлением, если оно разрешено, иначе подсказкой с кнопкой «Открыть»;
это работает и в Grid Work.

Когда Grid закрыт, напоминает календарь телефона — кнопка «Добавить в
календарь телефона» в задаче (см. ниже).

*При совместной работе* напоминания на закрытом Grid можно включить и
push-уведомлениями (нужна функция `grid-push`, шаг 6 ниже). На сервер уходят только время
каждого напоминания на 60 дней вперёд и случайный номер — без названия,
описания и типа задачи. Номера каждый раз новые, аккаунт не нужен:
устройство узнаётся по случайному ключу, на сервере хранится только его
отпечаток. Когда push приходит, телефон сам находит задачу по номеру и
показывает название. Если задан PIN, название по умолчанию скрыто — в
уведомлении только «Grid Life» и время; показ названия включается в
настройках. Список на сервере обновляется при каждом изменении задач и
открытии Grid: если не открывать Grid Life дольше 60 дней, напоминания
повторяющихся задач закончатся.

«Добавить в календарь телефона» в задаче сохраняет файл `.ics` с
повтором, напоминаниями и всем сроком многодневной задачи: Календарь iPhone и Outlook напомнят даже без
интернета (Google Календарь напоминания из файла не берёт).

Данные Grid Life хранятся только на устройстве (IndexedDB, с запросом
постоянного хранения) и никуда не отправляются (при совместной работе — кроме
времени push-напоминаний, если их включить). Grid устанавливается на
главный экран и открывается без интернета (`manifest.webmanifest`, `sw.js`).

**Настройки Grid Life** (на этом устройстве):
- *Календарь* — вид при открытии, первый день недели (понедельник или
  воскресенье), 24-часовой формат, длительность новой задачи, что делать
  с просроченными (блок «Просрочено» или перенос на сегодня), скрывать ли
  выполненное в прошедших днях.
- *Напоминания* — о каких задачах, напоминание по умолчанию, время для
  задач на весь день, разрешение на системные уведомления, показывать ли
  название задачи в уведомлении (при совместной работе — ещё push на
  закрытом Grid с пробным).
- *Типы задач* — все в одном месте: стандартные можно переименовать,
  перекрасить и убрать из списка (у задач они останутся), свои — создать,
  изменить, удалить.
- *Приватность* — PIN из четырёх цифр: его спрашивают при каждом переходе
  в Grid Life и при открытии приложения. Это защита экрана, а не
  шифрование. Забытый PIN сбрасывается только вместе с данными Grid Life
  (после двух подтверждений). Можно всегда открывать приложение в Grid Life.
  После PIN Grid предлагает вход по Face ID (Touch ID, Windows Hello):
  это ключ доступа (passkey) на самом устройстве, сервер не нужен. Face ID
  спрашивается сразу; если его отменили или он не сработал — ввод PIN,
  кнопка «Ввести PIN» видна всегда. Ключ появляется в «Паролях» iPhone и
  привязан к адресу сайта: при переезде Grid на другой адрес Face ID нужно
  включить заново. Если ключ удалили, Grid пускает по PIN и предлагает
  настроить Face ID снова.
- *Хранилище* — сколько места занято, постоянное хранение, удаление
  выполненных задач старше месяца, трёх месяцев, полугода или года,
  удаление всех данных Grid Life (вместе с его снимками) — с предложением
  сначала сохранить копию и вторым подтверждением.
- *Папка Grid*, *Резервная копия* и *Снимки* — те же разделы, что в
  Grid Work (см. «Папка Grid» и «Резервная копия» ниже); кнопка
  «Восстановить» у снимка здесь возвращает Grid Life.
- *На главный экран* — установка как приложения. *О Grid* — тот же раздел,
  что в настройках Grid Work.

**Проекты.** Кнопка боковой панели слева от логотипа выдвигает список
проектов: переключиться, создать, удалить. Сам логотип — просто надпись.
Каждый проект — самостоятельная доска со своей командой, колонками,
статусами и задачами.

**Участники.** Значок участников в шапке открывает список имён — кого
можно назначить ответственным и выбрать в фильтре. Список общий для всех
проектов: добавить, переименовать, удалить (задачи удалённого остаются без
ответственного). Первый в нём — вы: кнопка с вашим именем открывает
профиль — имя, фото и цвет.

**Команда и роли** (при совместной работе). Значок участников открывает команду проекта.
Владелец приглашает коллегу по почте его Google-аккаунта и выбирает роль;
доступ открывается, когда человек входит в Grid с этой почтой. Роли:
владелец — всё, включая участников, статусы и типы, удаление колонок и
проектов; редактор — задачи, колонки, заметки и файлы; наблюдатель —
смотрит и комментирует. Ответственным можно назначить только вошедшего
участника проекта. Права держит база (правила RLS), а не только
интерфейс. В профиле при совместной работе — ещё почта и выход.

**Вкладки над колонками.** Доска · Диаграмма Ганта · Календарь ·
Заметки и файлы · Архив. Гант и календарь строятся по датам той же доски.

**Календарь Grid Work.** Виды Месяц, Неделя, День и Список, стрелки,
«Сегодня», на телефоне — свайп влево и вправо. Задача с началом и
дедлайном идёт полосой через все дни этого срока, как многодневное
событие в Google Календаре, задача с одной датой — в свой день. Цвет —
тип задачи. На телефоне в месяце под числом до трёх точек цвета типа, а
задачи выбранного дня — списком ниже. Фильтры доски (участник,
приоритет, «Скрыть выполненные») действуют и здесь. Нажатие на задачу
открывает её панель, нажатие на пустой день создаёт задачу с этой датой в
первой колонке.

**Задача.** Чекбокс с зачёркиванием, статус, тип задачи с иконкой,
приоритет с цветом, ответственный, даты начала и дедлайна, подзадачи,
вложенные файлы, описание и комментарии — записи к задаче со временем
(при совместной работе — ещё и с автором). Задача
открывается нажатием на карточку. Меню «⋮» на карточке: закрепить или
открепить (закреплённые задачи всегда вверху колонки, с булавкой, и при
сортировке тоже), добавить подзадачу, убрать в архив, цвет карточки,
удалить. Цвет карточки — светлый оттенок из общей палитры, его можно
выбрать и в панели задачи; полоска приоритета слева остаётся.

**Цвета.** Одна палитра из десяти ярких цветов — синий, голубой,
бирюзовый, зелёный, жёлтый, оранжевый, красный, розовый, фиолетовый,
серый — для типов задач (в Grid Work и Grid Life), статусов, заметок и
карточек. В метке иконка и точка яркие, фон — светлый оттенок, текст
тёмный и хорошо читается.

**Типы задач.** Стандартные (Отчёты, Обучение, Улучшайзинг, Идея,
Заметка, Срочно) плюс свои: «+ Свой тип» в панели задачи — название,
цвет и иконка из набора. Свои типы хранятся в проекте; создаёт, меняет
и удаляет их владелец (карандаш рядом с «+ Свой тип»).

**Статусы.** У каждого проекта свои, новый проект получает пять
стандартных. Владелец настраивает их кнопкой «Настроить» рядом с полем
статуса: добавить, переименовать, перекрасить, удалить. Если статус стоит
у задач, при удалении доска спросит, на какой статус их перевести. Статус
«Готова» ставится выполненным задачам, поэтому его можно переименовать,
но не удалить. Задача, переехавшая в другой проект, получает статус и
свой тип с тем же названием (или начальный статус); ответственный, если
его нет в новом проекте, снимается.

**Подзадачи.** Это отдельные карточки со своим чекбоксом, меню «⋮»,
дедлайном, приоритетом и ответственным; открываются в такой же панели,
как задача. На карточке родителя — прогресс «3/11» и стрелка, которая
раскрывает подзадачи прямо в колонке. Подзадача живёт под родителем и
переезжает вместе с ним. Через «⋮» её можно сделать отдельной задачей.

**Колонки.** Создать, перетащить и всё остальное — через меню «⋮» в
шапке колонки: переименовать, архивировать все задачи или только
выполненные, переместить в другой проект (вместе с задачами), дублировать
(копия встаёт справа, с задачами и подзадачами, но без комментариев и
файлов), разово отсортировать задачи — по дедлайну, ответственному, дате
создания, выполненности, названию, приоритету, типу или статусу, по
возрастанию или убыванию. Там же перенос выполненных задач и цвет шапки:
ряд пастельных и ряд насыщенных цветов.

**Архив.** Задача уходит в архив вместе с подзадачами и пропадает с
доски, Ганта и календаря. Во вкладке «Архив» её можно вернуть в конец
своей колонки или удалить.

**Корзина.** Удалённые задачи (с подзадачами), колонки (с задачами) и
проекты 30 дней лежат в корзине в настройках, потом стираются насовсем.
Сразу после удаления внизу появляется кнопка «Вернуть». При совместной
работе задачи удаляют и возвращают владелец и редакторы, колонки и
проекты — только владелец; стереть насовсем до срока может только владелец.

**Настройки** (шестерёнка внизу боковой панели или кнопка с вашим
именем). *Вы и участники:* профиль (имя, фото или инициалы, цвет),
список участников, отображение (вид при открытии, обычные или
компактные карточки, первый день недели, формат даты, скрывать ли
выполненные) и уведомления. *Проект:* название и описание, перенос
выполненных для новых колонок, статусы и свои типы. *Данные:* папка Grid
(на компьютере), резервная копия и напоминание о ней, снимки, место в
браузере, постоянное хранение, «Очистить и начать с нуля», корзина. *О Grid* (тот же раздел есть в
настройках Grid Life): версия, «Сотрудничество и отзывы» — ссылка на
Telegram из поля `telegram` в [`grid.config.js`](grid.config.js),
конфиденциальность, условия и лицензии.
При совместной работе настройки делятся на личные и командные (участники
и роли, «Доступ к Grid» для владельца Grid, подписка на календари).

**Папка Grid** (компьютер; Chrome, Edge, Яндекс Браузер — где браузер умеет
работать с папками). Данные Grid Work и Grid Life живут в выбранной
папке, браузер — рабочая копия; на сервер по-прежнему ничего не уходит.
- *Первый запуск.* Если Grid открылся без данных (впервые или после
  очистки браузера — их не различить), он показывает экран «Данные Grid
  на этом компьютере»: «Найти мои данные» (папка, где Grid уже хранил
  данные, — загрузится последняя версия), «Выбрать папку для данных»
  (впервые — Grid начнёт с примера) и «Начать с нуля без папки». Папку
  можно подключить и позже: Настройки → Данные → «Папка Grid».
- *Запись.* Через 3–5 секунд после правки Grid записывает в папку
  `grid.json` — всё состояние обоих режимов (с корзиной и PIN Grid Life),
  вложения — отдельными файлами в `files/`, каждое один раз. В шапке —
  «Сохранено в папку · только что» или предупреждение, если запись не
  удалась; то же в настройках.
- *История* — `history/`: по одной версии за день (последнее состояние
  дня) за 7 последних дней работы и версии, отложенные при выборе; в
  настройках у каждой — «Загрузить» (то, что было, ляжет в историю).
- *Доступ.* Если браузер забыл разрешение на папку (Chrome после
  перезапуска), вверху — «Разрешить доступ к папке Grid»; правки тем
  временем копятся в браузере и записываются после разрешения. Чтобы не
  спрашивал снова, в окне браузера — «Разрешать при каждом посещении».
- *Другой компьютер.* Если папка синхронизируется облаком и её файл
  записал другой компьютер или браузер, Grid предлагает загрузить его.
  Сам Grid ничего не сливает: если изменения есть и здесь, и там, он
  предупреждает и даёт выбрать, какую версию оставить, — вторая ложится
  в историю папки.
- Пока папка подключена, напоминания о резервной копии нет. Прежние
  «автокопии в папку» стали папкой Grid: та же папка, теперь с
  `grid.json`, `files/` и `history/`.

**Резервная копия.** Там, где папки Grid нет, данные живут только в
браузере, поэтому копия — на вас; на сервер ничего не уходит. Раздел
«Резервная копия» один и тот же в настройках Grid Work и Grid Life.
- *Копия* — один файл со всем Grid: проекты Grid Work (колонки, задачи с
  подзадачами и комментариями, заметки, статусы, типы, участники, файлы)
  и Grid Life (задачи, типы, файлы и настройки, без PIN). Корзина в копию
  не входит. «Сохранить копию» на телефоне открывает меню «Поделиться» с
  файлом («Сохранить в Файлы», iCloud Drive, Telegram), на компьютере —
  скачивает его. Если Grid Life закрыт PIN, копия из Grid Work сначала
  спрашивает PIN — или сохраняется без Grid Life.
- *Напоминание* — раз в неделю (можно раз в месяц или не напоминать) над
  доской и над списком Grid Life; его кнопка сразу сохраняет копию.
- *Восстановить из файла* — принимает и общую копию, и прежние отдельные
  копии Grid Work и Grid Life; можно вернуть всё или одну часть.
  Проекты Grid Work добавляются как новые и ничего существующего не
  меняют; ответственные находятся в списке участников по имени, а кого
  нет — добавляются. Задачи Grid Life заменяют текущие. При совместной
  работе вы становитесь владельцем восстановленных проектов, а команда из
  копии получает приглашения с прежними ролями.

**Снимки.** Раз в день при открытии Grid сохраняет снимок Grid Work и
Grid Life здесь же, на устройстве, и хранит последние 7 (если ничего не
менялось, новый не нужен). Снимок выручает после ошибки — «Восстановить»
в настройках Grid Work возвращает Grid Work, в настройках Grid Life —
Grid Life, другой режим не меняется; перед этим Grid предлагает сохранить
текущее состояние снимком, чтобы можно было вернуться. От удаления
приложения, очистки браузера или смены устройства снимки не спасают —
для этого копия.

**Календари.** В панели задачи с датами — «Google Календарь» (готовое
событие; название и даты задачи будут переданы в ваш Google Календарь) и
«Файл .ics» (для Outlook, Apple Календаря и других). При совместной
работе в настройках каждый получает ещё и личную
ссылку для подписки: задачи с датами сами появляются в его Google
Календаре или Outlook — только свои или все задачи его проектов. Календарь
забирает изменения раз в несколько часов (Google — бывает и до суток),
ускорить это нельзя; правки в календаре в доску не возвращаются.
Событие ведёт ссылкой прямо на задачу в доске.

**Уведомления.** Пока Grid открыт, он напоминает о дедлайнах ваших задач
и задач без ответственного — за день и в день дедлайна, в 9:00, с учётом
тихих часов (по умолчанию с 22:00 до 8:00). Если браузер разрешил
системные уведомления, напоминание приходит и в свёрнутую вкладку. Чтобы
напомнило, когда Grid закрыт, «Файл .ics» в настройках уведомлений
сохраняет все невыполненные дедлайны с напоминаниями для календаря телефона.

*При совместной работе* — push на телефон и компьютер, даже когда Grid закрыт:
- дедлайн — за день и в день дедлайна, в 9:00 по времени телефона;
- вас назначили ответственным;
- комментарий к вашей задаче.

Приходят ответственному, а у задачи без ответственного — её автору. О
своих действиях (назначил сам себя, сам написал комментарий) Grid не
сообщает. В настройках каждый включает уведомления на своём устройстве,
выбирает события и тихие часы (по умолчанию с 22:00 до 8:00): то, что
пришлось на них, приходит, когда они закончатся. Нажатие на уведомление
открывает задачу. При выходе из аккаунта устройство перестаёт получать
уведомления. На iPhone push приходит только в Grid, добавленный на экран
«Домой» (iOS 16.4 и новее). Как включить на сервере — шаг 6 ниже.

**Заметки проекта.** Во вкладке «Заметки и файлы» кнопка «+ Заметка»
создаёт новую. У заметки есть название, цвет и тип: стандартные
(Заметка, Договорённость, Встреча, Инструкция, Ссылки, Идея) плюс свои,
как у задач. К заметке можно прикрепить файлы и картинки — с теми же
ограничениями, что у задач (до 10 МБ, фото сжимаются): картинки видны
превью прямо в заметке и открываются на весь экран, остальные файлы —
списком с названием и размером.

### Две особенности, о которых стоит знать

Отметка «выполнено» **переносит задачу в другую колонку** — по
умолчанию в следующую. В меню колонки можно выбрать другую колонку,
в том числе в другом проекте, или выключить перенос: тогда задача
остаётся на месте. Снятие галочки задачу не возвращает. Подзадачи при
выполнении никуда не переезжают.

Перетаскивание рассчитано на мышь. На телефоне задачу переносят через
поле «Колонка» в панели задачи.

## Совместная работа (второй этап)

Сейчас Grid работает только на устройстве. Чтобы включить совместную
работу через сервер, нужен проект Supabase (шаги ниже) и `collab: true` в
[`grid.config.js`](grid.config.js) — вместе с адресом проекта и ключом
`anon`. Серверные файлы уже в репозитории: `supabase-schema.sql` и
`supabase/functions/`. С `collab: true` Grid Work просит войти и хранит
доски в базе; Grid Life по-прежнему хранит задачи на устройстве.

Что включается: вход через Google (или почту) только по приглашению,
команда с ролями владелец / редактор / наблюдатель и приглашения,
список доступа для владельца Grid, push-уведомления Grid Work, подписка
на календари по ссылке, push-напоминания Grid Life (на сервер уходят
только время и случайный номер), библиотека supabase-js с CDN.
Локальные данные Grid Work при этом в базу сами не переезжают — их
переносят резервной копией.

Шаги — один раз:

### 1. Создать проект Supabase

[supabase.com](https://supabase.com) → New project.

### 2. Создать таблицы и хранилище

Supabase → **SQL Editor** → вставить целиком файл
[`supabase-schema.sql`](supabase-schema.sql) → **Run**.

Скрипт создаёт таблицы, правила доступа по ролям, приватный бакет
`grid-files` для вложений (файл до 10 МБ) и включает живые обновления.
Без входа не видно ни строки, после входа — только проекты, где человек
участник. Скрипт можно запускать повторно — например, после обновления Grid.

**Вписать себя владельцем Grid.** Войти в Grid Work можно только по
приглашению: с почтой, которую пригласили в проект, или из списка доступа.
Сначала в нём нет никого, поэтому один раз там же, в SQL Editor:

```sql
insert into public.grid_access (email, admin) values ('ваша@почта', true)
on conflict (email) do update set admin = true;
```

Теперь вы можете войти, создать первый проект и приглашать команду. Список
доступа — в настройках доски, раздел «Доступ к Grid» (видите только вы):
туда добавляют, например, друзей, у которых пока нет проекта.

### 3. Включить вход через Google

**а) Google Cloud.** [console.cloud.google.com](https://console.cloud.google.com)
→ APIs & Services → Credentials → Create credentials → **OAuth client ID** →
тип **Web application**. В поле *Authorized redirect URIs* вставить:

```
https://<ВАШ-ПРОЕКТ>.supabase.co/auth/v1/callback
```

Скопировать **Client ID** и **Client secret**.

**б) Supabase.** Authentication → Providers → **Google** → включить,
вставить Client ID и Client secret → Save.

**в) Supabase.** Authentication → URL Configuration:

- *Site URL:* `https://iliaeov-tech.github.io/grid/grid.html`
- *Redirect URLs:* добавить туда же `https://iliaeov-tech.github.io/grid/grid.html`
  (и больше ничего — других адресов для возврата после входа быть не должно)

**г) Не заводить аккаунты чужим.** Authentication → Hooks → **Before User
Created** → Postgres → схема `public`, функция `grid_before_user_created`
→ Save. Тогда Supabase не создаст аккаунт почте, которой нет ни в одном
проекте и в списке доступа, а человек увидит на экране входа «Grid Work
открыт только по приглашению». Без этого шага защита всё равно работает:
такой человек войдёт, но Grid сразу его выпустит с тем же объяснением, и
база не даст ему ничего создать.

**д)** Authentication → Providers: оставить включённым только Google (или
то, чем вы входите), анонимный вход (*Anonymous sign-ins*) — выключен.

### 4. Прописать ключи в доску

Supabase → Project Settings → API. Оттуда нужны **Project URL** и ключ
**anon**. Вставить их в [`grid.config.js`](grid.config.js) и закоммитить.

Через минуту после пуша доска заработает по адресу выше.

> Ключ `anon` не секретный: он рассчитан на публикацию в браузере и не даёт
> обойти права доступа. Данные защищают вход через Google и правила RLS.
> Ключ `service_role` в этот репозиторий класть нельзя — он даёт полный
> доступ к базе в обход всех правил.

### 5. Подписка на календарь (по желанию)

Ссылки на календарь из настроек отдаёт функция Supabase из файла
[`supabase/functions/grid-calendar/index.ts`](supabase/functions/grid-calendar/index.ts).
Её нужно развернуть один раз — любым из двух способов.

**В браузере.** Supabase → Edge Functions → Deploy a new function →
Via Editor. Имя — `grid-calendar`, вместо примера вставить содержимое
файла целиком → Deploy. Затем в настройках функции выключить проверку
JWT (Verify JWT / Enforce JWT verification).

**Из командной строки** (нужен Node.js), в папке репозитория:

```
npx supabase login
npx supabase functions deploy grid-calendar --no-verify-jwt --project-ref <ВАШ-ПРОЕКТ>
```

`<ВАШ-ПРОЕКТ>` — часть адреса до `.supabase.co`.

Проверка JWT выключается потому, что приложения календаря не умеют
входить через Google; задачи по ссылке защищает секретный токен в ней.
Ключи функции не нужны — Supabase подставляет их сам. Если доска
переедет на другой адрес, задайте его в Edge Functions → Secrets как
`GRID_URL`, чтобы ссылки из событий вели на новое место.

Как проверить: создайте ссылку в настройках доски и откройте её в
браузере — должен скачаться или открыться текст, начинающийся с
`BEGIN:VCALENDAR`.

### 6. Уведомления (по желанию)

Push о задачах Grid Work и напоминания Grid Life рассылает функция
Supabase из файла
[`supabase/functions/grid-push/index.ts`](supabase/functions/grid-push/index.ts).
Раз в минуту её вызывает задание по расписанию. Сначала выполните шаги
1–4: таблицы для уведомлений входят в `supabase-schema.sql`.

1. **Ключи для push (VAPID).** В терминале (нужен Node.js):

   ```
   npx web-push generate-vapid-keys
   ```

   Команда покажет два ключа: Public Key и Private Key. Приватный ключ
   секретный — не вставляйте его в репозиторий и не пересылайте.
2. **Секреты функции.** Supabase → Edge Functions → Secrets → добавить три:
   - `VAPID_PUBLIC_KEY` — Public Key;
   - `VAPID_PRIVATE_KEY` — Private Key;
   - `VAPID_SUBJECT` — `mailto:` и почта для связи, например
     `mailto:you@example.com`. Её видят только службы доставки push
     (Apple, Google), если с рассылкой что-то не так.
3. **Развернуть функцию** — так же, как `grid-calendar` в шаге 5, с
   именем `grid-push` и с выключенной проверкой JWT. Из командной строки:

   ```
   npx supabase functions deploy grid-push --no-verify-jwt --project-ref <ВАШ-ПРОЕКТ>
   ```

   Проверка JWT выключена, потому что задание по расписанию и Grid Life
   (он работает без аккаунта) входить не умеют. Вместо неё рассылку
   защищает секрет задания (шаг 4), а запросы Grid Life — лимиты частоты
   (с одного адреса, от одного устройства) и потолок новых устройств в базе.
4. **Расписание.** Supabase → SQL Editor → выполнить, подставив свой адрес
   проекта:

   ```sql
   create extension if not exists pg_cron;
   create extension if not exists pg_net with schema extensions;
   -- секрет задания: случайная строка в Vault, вводить ничего не нужно
   select vault.create_secret(replace(gen_random_uuid()::text || gen_random_uuid()::text, '-', ''), 'grid_cron_secret');
   select cron.schedule('grid-push', '* * * * *', $$
     select net.http_post(
       url := 'https://<ВАШ-ПРОЕКТ>.supabase.co/functions/v1/grid-push',
       headers := jsonb_build_object('Content-Type', 'application/json', 'x-grid-cron',
         (select decrypted_secret from vault.decrypted_secrets where name = 'grid_cron_secret')),
       body := '{"run": true}'::jsonb)
   $$);
   ```

   Рассылку запускает только это задание: функция проверяет секрет из
   Vault, остальные получают отказ. Это около 43 000 вызовов в месяц — в
   пределах бесплатного плана (500 000). Остановить:
   `select cron.unschedule('grid-push');`
5. **Включить на устройстве.** iPhone: откройте Grid в Safari →
   «Поделиться» → «На экран „Домой“» → запустите Grid с иконки →
   Настройки → Уведомления → включить → «Разрешить». Компьютер и
   Android — то же в браузере. Кнопка «Прислать пробное» проверит доставку.

Как проверить: откройте в браузере
`https://<ВАШ-ПРОЕКТ>.supabase.co/functions/v1/grid-push` — должен
прийти открытый ключ (`{"key": "B…"}`). Ответ «Уведомления не
настроены» значит, что секреты VAPID не заданы.

### 7. Позвать команду

Войдите первым (вы уже в списке доступа, шаг 2) и создайте проект — вы его
владелец. Затем значок участников в шапке → почта коллеги и роль →
«Пригласить». Письмо Grid не отправляет: пришлите коллеге ссылку на доску
сами. Когда он войдёт через Google с этой почтой, проект появится у него
автоматически. Приглашение и есть допуск: без него и без списка доступа
войти в Grid Work нельзя.

## Как устроено

| Файл | Назначение |
|---|---|
| `grid.html` | Оболочка и Grid Work: разметка, стили, логика |
| `life.js`, `life.css` | Grid Life — личный календарь |
| `sw.js`, `manifest.webmanifest`, `icons/` | Установка на главный экран и работа без сети |
| `fonts/` | Шрифты сайта (woff2, кириллица и латиница) и тексты их лицензий (OFL) |
| `grid.config.js` | Переключатель совместной работы `collab`, адрес проекта Supabase и публичный ключ |
| `supabase-schema.sql` | Таблицы, права доступа, бакет файлов, живые обновления |
| `supabase/functions/grid-calendar/index.ts` | Календарь для подписки по секретной ссылке |
| `supabase/functions/grid-push/index.ts` | Push-уведомления Grid Work и напоминания Grid Life |
| `index.html` | Перенаправление с корня на `grid.html` |

Хранилище спрятано за адаптером (`supaStore` / `localStore` в `grid.html`)
с четырьмя операциями: `subscribe`, `set`, `update`, `del`. Смена базы —
это замена одного адаптера, остальной код её не видит. Соответствие
полей в браузере колонкам базы задаёт одна таблица `MAP`.

Без совместной работы Grid Work хранит те же коллекции в IndexedDB
`grid-work` (`localStore`), Grid Life — в своей `grid-life`. В памяти —
копия, каждая правка сразу пишется на диск; файлы лежат как есть (Blob).
Служебное (`meta`): кто хозяин устройства, показан ли пример. Код
совместной работы включается одной проверкой `COLLAB` (из
`grid.config.js`): без неё не загружается supabase-js, не показываются
вход, роли, приглашения, push и подписка на календари.

Папку Grid, копию и снимки обоих режимов ведёт один модуль в `grid.html`
(«папка Grid, копия и снимки»); Grid Life отдаёт и принимает свои данные
через `GridLife.raw / load / copyPart / fromCopy / pin / setPin`. Копия —
JSON с `app: "grid"` и частями `work` (как прежняя копия `grid-work`) и
`life` (как прежняя `grid-life`). Снимки и служебное — в IndexedDB
`grid-backup`: `snaps` (строки обоих режимов), `blobs` (файлы, каждый
один раз по ключу `w:id` или `l:id`), `meta` (список снимков, папка Grid
и её метки, когда сохраняли копию). Без совместной работы данные Grid Work
грузятся при открытии в любом режиме — снимку и папке нужны оба. С
совместной работой Grid Work на сервере, в снимки идёт только Grid Life,
папки Grid нет.

Папка Grid: `grid.json` — `{app: "grid-folder", rev, savedAt, me, work, life}`,
строки как в снимке (`work` — все коллекции, `life` — задачи, типы, файлы,
настройки и `pin`), у вложений вместо данных — файл `files/w-<id>` или
`files/l-<id>`. `rev` — метка записи: в браузере помнят метку, время файла
и подпись данных последней синхронизации; другая метка в папке — файл
записал кто-то ещё, другая подпись в браузере — здесь есть несохранённое.
Первая запись нового дня кладёт прежний `grid.json` в
`history/grid-ГГГГ-ММ-ДД.json`; там же отложенные версии
`grid-ГГГГ-ММ-ДД ЧЧ-ММ <откуда>.json`. Вложения, которых нет ни в одной
версии, удаляются при смене дня.

Подзадача — обычная строка `cards` с `parent_id`. Свои типы задач и
заметок (`kinds`) и статусы (`statuses`) привязаны к проекту. Команда
проекта — `project_members`: строка с почтой и ролью, `user_id`
заполняется, когда приглашённый входит (`grid_after_login`). Профиль
человека — `profiles`: фото лежит в нём же маленькой картинкой (data:URL,
до 100 КБ), личные настройки отображения — в поле `settings`. Корзина —
отметка `deleted_at` у проектов, колонок и задач; просроченное стирает
браузер владельца при входе.

Push: устройства — `push_subscriptions`, очередь — `notifications`. Её
пополняют триггеры (назначение, комментарий) и функция `grid-push`
(дедлайны), рассылает тоже она. Напоминания Grid Life — `life_devices` и
`life_reminders`: время и случайный номер, без названий задач. Из
приложения эти таблицы не видны.

**Безопасность.** Права держит база, интерфейс их только отражает:
- войти в Grid Work могут приглашённые в любой проект и почты из
  `grid_access`; остальным база не даёт ничего создать (проект, профиль,
  ссылку календаря, подписку на уведомления);
- посторонний не видит и не меняет ничего в чужом проекте, наблюдатель
  только смотрит и комментирует; аноним (без входа) не имеет прав ни на одну
  таблицу и функцию;
- почту в профиле человек не меняет (приглашение привязывается по почте из
  Supabase Auth), путь файла в хранилище — только в папке своего проекта и
  неизменен, свой комментарий нельзя перенести в чужую задачу, автор задачи
  не меняется;
- служебные функции правил доступа лежат в схеме `private`, которую API не
  показывает; приложение зовёт только четыре функции (`grid_after_login`,
  `grid_storage_used`, `grid_push_subscribe`, `grid_push_unsubscribe`);
- весь текст из базы и из резервных копий выводится экранированным, цвета,
  приоритеты и значки — только из известных списков;
- «кто онлайн» — свой канал Realtime у каждого проекта.

Порядок карточек и колонок задаёт дробное число `pos`: при переносе
пересчитывается только сама карточка.

Файлы лежат в приватном бакете `grid-files`; ссылка на скачивание
выдаётся на две минуты. Без совместной работы вложения лежат в IndexedDB
как есть, с тем же лимитом 10 МБ на файл; общее место ограничивает браузер.

## Ограничения

- При совместной работе одновременная правка одного поля разными людьми
  разрешается по принципу «последний сохранил — тот и прав».
- В приватном окне Safari (во всяком случае в версии 18) вложения не
  сохраняются: WebKit там не хранит файлы в IndexedDB. В обычном окне и
  в установленном приложении всё работает.
- Классы CSS в `grid.html` живут в одном пространстве имён: перед тем как
  добавить модификатор вроде `chip talk`, проверьте, что такого класса нет
  у блока — иначе он унаследует чужую раскладку.
