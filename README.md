# Grid

Одно приложение, два режима:

- **Grid Work** — командные Kanban-доски: несколько проектов,
  неограниченные колонки, перетаскивание, подзадачи, дедлайны, файлы и
  комментарии, плюс те же задачи на диаграмме Ганта и в календаре.
  Данные — в Supabase.
- **Grid Life** — личный календарь задач. Данные хранятся только на
  устройстве; вход и интернет не нужны.

Страница — на GitHub Pages.

**Адрес доски:** https://iliaeov-tech.github.io/grid/grid.html

---

## Что умеет

**Режимы.** Переключатель справа от логотипа меняет режим: «Grid Work»
(синий акцент) или «Grid Life» (зелёный). Переключение мгновенное,
приложение запоминает последний режим на этом устройстве (или всегда
открывается в Grid Life — это настройка Grid Life). В Grid Life
скрыто всё рабочее — проекты, участники, фильтры и вкладки доски.
Grid Life открывается без входа; Grid Work без входа показывает экран
входа, но переключатель остаётся доступен. Ссылка на задачу из
календаря (`#task=…`) всегда открывает Grid Work.

**Grid Life — личный календарь.** Виды: список по дням (основной),
день, неделя, месяц; кнопка «Сегодня». Задача: название, дата, время
или «весь день», необязательное время окончания, тип с иконкой и цветом
(Дела, Встреча, Здоровье, Спорт, Покупки, Учёба, Семья, Финансы плюс
свои), приоритет, файлы, короткое описание, чекбокс выполнения.
Невыполненные задачи прошлых дней — в блоке «Просрочено» вверху
списка, их можно перенести на сегодня по одной или все сразу; задачи
без даты — в «Без даты». Создать задачу — кнопка «+», касание по дню в
списке, по времени в дне и неделе, второе касание дня в месяце. В
боковой панели — виды и типы: снятая галочка скрывает задачи типа.

**Повторяющиеся задачи.** Каждый день, каждую неделю (по выбранным дням),
каждые 2 недели, каждый месяц, каждый год или свой интервал — каждые N
дней, недель, месяцев или лет. Окончание: бессрочно, до даты, после N
раз, плюс быстрые «Месяц» и «Год». Если в месяце нет нужного числа
(31-е, 29 февраля), повтор пропускается, как в Google Календаре.
Выполнение повтора отмечает только его. Изменение или удаление
повторяющейся задачи спрашивает: «Только эту», «Эту и последующие» или
«Все». В «Просрочено» от серии попадает только последний пропущенный
повтор.

Данные Grid Life хранятся только на устройстве (IndexedDB, с запросом
постоянного хранения) и никуда не отправляются. Grid устанавливается на
главный экран и открывается без интернета (`manifest.webmanifest`, `sw.js`).

**Настройки Grid Life** (на этом устройстве):
- *Календарь* — вид при открытии, первый день недели (понедельник или
  воскресенье), 24-часовой формат, длительность новой задачи, что делать
  с просроченными (блок «Просрочено» или перенос на сегодня), скрывать ли
  выполненное в прошедших днях.
- *Типы задач* — все в одном месте: стандартные можно переименовать,
  перекрасить и убрать из списка (у задач они останутся), свои — создать,
  изменить, удалить.
- *Приватность* — PIN из четырёх цифр: его спрашивают при каждом переходе
  в Grid Life и при открытии приложения. Это защита экрана, а не
  шифрование. Забытый PIN сбрасывается только вместе с данными Grid Life
  (после двух подтверждений). Можно всегда открывать приложение в Grid Life.
  После PIN Grid предлагает вход по Face ID (Touch ID, Windows Hello):
  это ключ доступа (passkey) на самом устройстве, сервер не нужен. Face ID
  спрашивается сразу; если его отменили или он не сработал — ввод PIN,
  кнопка «Ввести PIN» видна всегда. Ключ появляется в «Паролях» iPhone и
  привязан к адресу сайта: при переезде Grid на другой адрес Face ID нужно
  включить заново. Если ключ удалили, Grid пускает по PIN и предлагает
  настроить Face ID снова.
- *Хранилище* — сколько места занято, постоянное хранение, резервная
  копия (с настройками, без PIN) и восстановление, напоминание о копии
  (раз в неделю, раз в месяц или никогда), удаление выполненных задач
  старше месяца, трёх месяцев, полугода или года, удаление всех данных
  Grid Life — с предложением сначала сохранить копию и вторым подтверждением.

**Проекты.** Кнопка боковой панели слева от логотипа выдвигает список
проектов: переключиться, создать, удалить. Сам логотип — просто надпись.
Каждый проект — самостоятельная доска со своей командой, колонками,
статусами и задачами.

**Команда и роли.** Значок участников в шапке открывает команду проекта.
Владелец приглашает коллегу по почте его Google-аккаунта и выбирает роль;
доступ открывается, когда человек входит в Grid с этой почтой. Роли:
владелец — всё, включая участников, статусы и типы, удаление колонок и
проектов; редактор — задачи, колонки, заметки и файлы; наблюдатель —
смотрит и комментирует. Ответственным можно назначить только вошедшего
участника проекта. Права держит база (правила RLS), а не только
интерфейс. Кнопка с вашим именем открывает профиль: имя, цвет, выход.
В демо там же можно посмотреть доску глазами примера с другой ролью.

**Вкладки над колонками.** Доска · Диаграмма Ганта · Календарь ·
Заметки и файлы · Архив. Гант и календарь строятся по датам той же доски.

**Задача.** Чекбокс с зачёркиванием, статус, тип задачи с иконкой,
приоритет с цветом, ответственный, даты начала и дедлайна, подзадачи,
вложенные файлы, описание и комментарии с автором и временем. Задача
открывается нажатием на карточку. Меню «⋮» на карточке: закрепить или
открепить (закреплённые задачи всегда вверху колонки, с булавкой, и при
сортировке тоже), добавить подзадачу, убрать в архив, цвет карточки,
удалить. Цвет карточки — светлый оттенок из общей палитры, его можно
выбрать и в панели задачи; полоска приоритета слева остаётся.

**Цвета.** Одна палитра из десяти ярких цветов — синий, голубой,
бирюзовый, зелёный, жёлтый, оранжевый, красный, розовый, фиолетовый,
серый — для типов задач (в Grid Work и Grid Life), статусов, заметок и
карточек. В метке иконка и точка яркие, фон — светлый оттенок, текст
тёмный и хорошо читается.

**Типы задач.** Стандартные (Отчёты, Обучение, Улучшайзинг, Идея,
Заметка, Срочно) плюс свои: «+ Свой тип» в панели задачи — название,
цвет и иконка из набора. Свои типы хранятся в проекте; создаёт, меняет
и удаляет их владелец (карандаш рядом с «+ Свой тип»).

**Статусы.** У каждого проекта свои, новый проект получает пять
стандартных. Владелец настраивает их кнопкой «Настроить» рядом с полем
статуса: добавить, переименовать, перекрасить, удалить. Если статус стоит
у задач, при удалении доска спросит, на какой статус их перевести. Статус
«Готова» ставится выполненным задачам, поэтому его можно переименовать,
но не удалить. Задача, переехавшая в другой проект, получает статус и
свой тип с тем же названием (или начальный статус); ответственный, если
его нет в новом проекте, снимается.

**Подзадачи.** Это отдельные карточки со своим чекбоксом, меню «⋮»,
дедлайном, приоритетом и ответственным; открываются в такой же панели,
как задача. На карточке родителя — прогресс «3/11» и стрелка, которая
раскрывает подзадачи прямо в колонке. Подзадача живёт под родителем и
переезжает вместе с ним. Через «⋮» её можно сделать отдельной задачей.

**Колонки.** Создать, перетащить и всё остальное — через меню «⋮» в
шапке колонки: переименовать, архивировать все задачи или только
выполненные, переместить в другой проект (вместе с задачами), дублировать
(копия встаёт справа, с задачами и подзадачами, но без комментариев и
файлов), разово отсортировать задачи — по дедлайну, ответственному, дате
создания, выполненности, названию, приоритету, типу или статусу, по
возрастанию или убыванию. Там же перенос выполненных задач и цвет шапки:
ряд пастельных и ряд насыщенных цветов.

**Архив.** Задача уходит в архив вместе с подзадачами и пропадает с
доски, Ганта и календаря. Во вкладке «Архив» её можно вернуть в конец
своей колонки или удалить.

**Корзина.** Удалённые задачи (с подзадачами), колонки (с задачами) и
проекты 30 дней лежат в корзине в настройках, потом стираются насовсем.
Сразу после удаления внизу появляется кнопка «Вернуть». Задачи
удаляют и возвращают владелец и редакторы, колонки и проекты — только
владелец; стереть насовсем до срока может только владелец.

**Настройки** (шестерёнка внизу боковой панели или кнопка с вашим
именем). *Лично для вас:* профиль (имя, фото или инициалы, цвет, выход),
отображение (вид при открытии, обычные или компактные карточки, первый
день недели, формат даты, скрывать ли выполненные) и календари. Эти
настройки хранятся в профиле и одинаковы на всех ваших устройствах.
*Проект:* название и описание, перенос выполненных для новых колонок,
участники и роли, статусы и свои типы — меняет владелец, остальные видят.
*Данные:* резервная копия, место для файлов (из 1 ГБ бесплатного плана)
и корзина. *О Grid:* версия и кнопка «Сообщить о проблеме или
предложить идею».

**Резервная копия.** Бесплатный план Supabase копий не хранит, поэтому
сохраняйте их сами — например раз в неделю: Настройки → Данные →
«Сохранить копию». Это один файл с проектом (или всеми проектами):
колонки, задачи с подзадачами и комментариями, заметки, статусы, типы,
команда и сами файлы. Корзина в копию не входит. «Восстановить из файла»
добавляет проекты как новые и ничего существующего не меняет: вы
становитесь владельцем, команда из копии получает приглашения с прежними
ролями. Ответственные сохраняются у тех, кто уже входил в Grid;
комментарии остальных восстанавливаются с именем автора.

**Календари.** В панели задачи с датами — «Google Календарь» (готовое
событие) и «Файл .ics» (для Outlook, Apple Календаря и других). А в
настройках (шестерёнка внизу боковой панели) каждый получает личную
ссылку для подписки: задачи с датами сами появляются в его Google
Календаре или Outlook — только свои или все задачи его проектов. Календарь
забирает изменения раз в несколько часов (Google — бывает и до суток),
ускорить это нельзя; правки в календаре в доску не возвращаются.
Событие ведёт ссылкой прямо на задачу в доске.

**Заметки проекта.** Во вкладке «Заметки и файлы» кнопка «+ Заметка»
создаёт новую. У заметки есть название, цвет и тип: стандартные
(Заметка, Договорённость, Встреча, Инструкция, Ссылки, Идея) плюс свои,
как у задач. К заметке можно прикрепить файлы и картинки — с теми же
ограничениями, что у задач (до 10 МБ, фото сжимаются): картинки видны
превью прямо в заметке и открываются на весь экран, остальные файлы —
списком с названием и размером.

### Две особенности, о которых стоит знать

Отметка «выполнено» **переносит задачу в другую колонку** — по
умолчанию в следующую. В меню колонки можно выбрать другую колонку,
в том числе в другом проекте, или выключить перенос: тогда задача
остаётся на месте. Снятие галочки задачу не возвращает. Подзадачи при
выполнении никуда не переезжают.

Перетаскивание рассчитано на мышь. На телефоне задачу переносят через
поле «Колонка» в панели задачи.

## Что нужно сделать один раз

Пока эти шаги не выполнены, доска открывается в демо-режиме: интерфейс
работает целиком, но задачи лежат только в браузере и коллеги их не видят.

### 1. Создать проект Supabase

[supabase.com](https://supabase.com) → New project.

### 2. Создать таблицы и хранилище

Supabase → **SQL Editor** → вставить целиком файл
[`supabase-schema.sql`](supabase-schema.sql) → **Run**.

Скрипт создаёт таблицы, правила доступа по ролям, приватный бакет
`grid-files` для вложений (файл до 10 МБ) и включает живые обновления.
Без входа не видно ни строки, после входа — только проекты, где человек
участник. Стартовых проектов нет: первый проект создаёт первый вошедший
и становится его владельцем. Скрипт можно запускать повторно — например,
после обновления Grid.

### 3. Включить вход через Google

**а) Google Cloud.** [console.cloud.google.com](https://console.cloud.google.com)
→ APIs & Services → Credentials → Create credentials → **OAuth client ID** →
тип **Web application**. В поле *Authorized redirect URIs* вставить:

```
https://<ВАШ-ПРОЕКТ>.supabase.co/auth/v1/callback
```

Скопировать **Client ID** и **Client secret**.

**б) Supabase.** Authentication → Providers → **Google** → включить,
вставить Client ID и Client secret → Save.

**в) Supabase.** Authentication → URL Configuration:

- *Site URL:* `https://iliaeov-tech.github.io/grid/grid.html`
- *Redirect URLs:* добавить туда же `https://iliaeov-tech.github.io/grid/grid.html`

### 4. Прописать ключи в доску

Supabase → Project Settings → API. Оттуда нужны **Project URL** и ключ
**anon**. Вставить их в [`grid.config.js`](grid.config.js) и закоммитить.
Там же поле `feedback` — почта, на которую уходят письма из кнопки
«Сообщить о проблеме или предложить идею». Пока оно пустое, кнопка
копирует сведения о версии, чтобы их можно было переслать.

Через минуту после пуша доска заработает по адресу выше.

> Ключ `anon` не секретный: он рассчитан на публикацию в браузере и не даёт
> обойти права доступа. Данные защищают вход через Google и правила RLS.
> Ключ `service_role` в этот репозиторий класть нельзя — он даёт полный
> доступ к базе в обход всех правил.

### 5. Подписка на календарь (по желанию)

Ссылки на календарь из настроек отдаёт функция Supabase из файла
[`supabase/functions/grid-calendar/index.ts`](supabase/functions/grid-calendar/index.ts).
Её нужно развернуть один раз — любым из двух способов.

**В браузере.** Supabase → Edge Functions → Deploy a new function →
Via Editor. Имя — `grid-calendar`, вместо примера вставить содержимое
файла целиком → Deploy. Затем в настройках функции выключить проверку
JWT (Verify JWT / Enforce JWT verification).

**Из командной строки** (нужен Node.js), в папке репозитория:

```
npx supabase login
npx supabase functions deploy grid-calendar --no-verify-jwt --project-ref <ВАШ-ПРОЕКТ>
```

`<ВАШ-ПРОЕКТ>` — часть адреса до `.supabase.co`.

Проверка JWT выключается потому, что приложения календаря не умеют
входить через Google; задачи по ссылке защищает секретный токен в ней.
Ключи функции не нужны — Supabase подставляет их сам. Если доска
переедет на другой адрес, задайте его в Edge Functions → Secrets как
`GRID_URL`, чтобы ссылки из событий вели на новое место.

Как проверить: создайте ссылку в настройках доски и откройте её в
браузере — должен скачаться или открыться текст, начинающийся с
`BEGIN:VCALENDAR`.

### 6. Позвать команду

Войдите первым и создайте проект — вы его владелец. Затем значок
участников в шапке → почта коллеги и роль → «Пригласить». Письмо Grid
не отправляет: пришлите коллеге ссылку на доску сами. Когда он войдёт
через Google с этой почтой, проект появится у него автоматически.

## Как устроено

| Файл | Назначение |
|---|---|
| `grid.html` | Оболочка и Grid Work: разметка, стили, логика |
| `life.js`, `life.css` | Grid Life — личный календарь |
| `sw.js`, `manifest.webmanifest`, `icons/` | Установка на главный экран и работа без сети |
| `grid.config.js` | Адрес проекта Supabase и публичный ключ |
| `supabase-schema.sql` | Таблицы, права доступа, бакет файлов, живые обновления |
| `supabase/functions/grid-calendar/index.ts` | Календарь для подписки по секретной ссылке |
| `index.html` | Перенаправление с корня на `grid.html` |

Хранилище спрятано за адаптером (`supaStore` / `localStore` в `grid.html`)
с четырьмя операциями: `subscribe`, `set`, `update`, `del`. Смена базы —
это замена одного адаптера, остальной код её не видит. Соответствие
полей в браузере колонкам базы задаёт одна таблица `MAP`.

Подзадача — обычная строка `cards` с `parent_id`. Свои типы задач и
заметок (`kinds`) и статусы (`statuses`) привязаны к проекту. Команда
проекта — `project_members`: строка с почтой и ролью, `user_id`
заполняется, когда приглашённый входит (`grid_after_login`). Профиль
человека — `profiles`: фото лежит в нём же маленькой картинкой (data:URL,
до 100 КБ), личные настройки отображения — в поле `settings`. Корзина —
отметка `deleted_at` у проектов, колонок и задач; просроченное стирает
браузер владельца при входе. Резервная копия — JSON с `app: "grid-work"`.

Порядок карточек и колонок задаёт дробное число `pos`: при переносе
пересчитывается только сама карточка.

Файлы лежат в приватном бакете `grid-files`; ссылка на скачивание
выдаётся на две минуты. В демо-режиме вложения хранятся прямо в браузере
и ограничены 400 КБ.

## Ограничения

- Одновременная правка одного поля разными людьми разрешается по принципу
  «последний сохранил — тот и прав».
- Классы CSS в `grid.html` живут в одном пространстве имён: перед тем как
  добавить модификатор вроде `chip talk`, проверьте, что такого класса нет
  у блока — иначе он унаследует чужую раскладку.
